## PHASE 3: ZIELSTRUKTUR

Mein-System/ (der Ordner, in dem wir gerade sind)
  CLAUDE.md                 Startdatei, wird bei jedem Start automatisch geladen. Schlank halten, höchstens etwa 100 Zeilen.
  AGENTS.md                 Hauptliste aller Agenten. Quelle der Wahrheit.
  .gitignore                schließt .env und private Dateien aus
  .claude/
    agents/                 Pro Agent eine schlanke Datei, damit Claude Code ihn als Helfer starten kann
    skills/                 Pro Skill ein Ordner mit SKILL.md
  Agents/
    00_Soul/AGENT.md        Identität, Stimme, Regeln. Wird von allen anderen nur gelesen.
    01_Brain/AGENT.md       Orchestrator
    02_Name/AGENT.md        weitere Agenten, immer Nummer plus Name
  Projects/                 Ein Ordner pro Projekt, nummeriert (01_Name ...)
    _Vorlage/CLAUDE.md      kleine Projektvorlage
  Wissen/                   Notizen, Recherchen, Archiv
  vorlagen/                 (liegt schon da)
  dashboard/                (liegt schon da)
  _Starter/                 Hierhin verschiebst du am Ende START_HIER.md, STARTER_PROMPT.txt und FOLGEPROMPTS.md

Wichtig, damit es technisch funktioniert:
- Skills müssen in .claude/skills/<name>/SKILL.md liegen, sonst findet Claude Code sie nicht von selbst.
- Agenten sind doppelt angelegt, aber ohne Doppelarbeit. Die ausführliche Beschreibung steht nur in Agents/NN_Name/AGENT.md. In .claude/agents/<name>.md steht nur eine kurze Datei mit Beschreibung und dem Auftrag "Lies zuerst Soul und deine AGENT.md". Die Dateien dafür liegen als Vorlage in vorlagen/.
- Soul und Brain bekommen keine Datei in .claude/agents. Sie laufen als Rolle der Hauptsitzung (Brain ist die Sitzung selbst, Soul wird per Import in CLAUDE.md geladen), denn Subagenten können in Claude Code keine weiteren Subagenten starten. Trage in deren AGENT.md Kopfblock "subagent: nein" ein.

## PHASE 5: SKILLS

Jeder Skill ist ein Ordner .claude/skills/<name>/SKILL.md nach vorlagen/SKILL_vorlage.md. Die description steht in EINER Zeile, beginnt mit "Nutze diesen Skill, wenn ..." und nennt Beispielsätze, denn daran erkennt Claude, wann der Skill gebraucht wird. Jeder Skill hat: wann nutzen und wann nicht, vorab klären (höchstens 4 Fragen), Prinzipien, Ablauf, Output Format, ein kurzes Beispiel. Schreibe aus deinem Fachwissen, nicht aus Füllsätzen, und zugeschnitten auf mein Interview.

PFLICHT
mein-kontext: ausführliches Wissen über mich (Business, Kompetenzen, Tools, Projekte, Stimme). Jeder Agent lädt ihn zuerst. Aus dem Interview gefüllt. Soul AGENT.md enthält nur das Kurzprofil und die Regeln, der Rest steht hier, damit nichts doppelt steht.
neuer-agent: legt auf einen Satz von mir einen neuen Agenten an. Schritte: nächste freie Nummer, AGENT.md und Subagent Datei aus den Vorlagen, Skills zuordnen oder anlegen, AGENTS.md und CLAUDE.md Tabelle aktualisieren, Dashboard neu bauen. Vorher höchstens 3 Fragen.
neuer-skill: legt einen neuen Skill an, ordnet ihn einem Agenten zu, baut das Dashboard neu. Wenn ich Text, Anleitung oder ein Dokument mitgebe, leitet er daraus den Ablauf ab.

system-check: Prüfliste für WatchTower: jeder Agent in beiden Orten vorhanden, jeder Skill hat eine description, keine toten Verweise, Hauptliste gleich Ordnerstand, CLAUDE.md nicht zu lang, keine Geheimnisse in Dateien.
